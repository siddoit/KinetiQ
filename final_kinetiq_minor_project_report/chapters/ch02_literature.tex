\chapter{LITERATURE REVIEW AND TECHNICAL BACKGROUND}

\section{Smart Mirrors and Ambient Wellness Interfaces}
Ambient Assisted Living (AAL) environments increasingly utilise smart mirrors as unobtrusive, daily-routine interfaces for ambient health monitoring. By integrating reflective surfaces with semi-transparent displays and embedded computing, smart mirrors allow individuals to review physiological trends during natural grooming routines without dedicated medical hardware. 

The seminal Wize Mirror project developed by Andreu et al.~\cite{andreu2016wize} established a multisensory smart-mirror platform aimed at cardio-metabolic risk prevention, integrating multispectral imaging, 3D optical scanning, and video photoplethysmography (PPG). While systems like the Wize Mirror illustrate the promise of ambient health hubs, they predominantly rely on complex, stationary physical sensor arrays or cloud processing pipelines. In consumer wellness contexts, smart mirrors must frequently integrate with third-party consumer wearables, introducing significant integration challenges regarding data provenance, transmission delay, and interface clarity.

\section{Wearable Health Integration and Mobile Relays}
Consumer wearable devices provide continuous tracking of biometrics including heart rate, peripheral oxygen saturation ($\mathrm{SpO_2}$), and physical activity~\cite{patel2012review,lara2013survey}. However, integrating consumer wearables into ambient dashboards is often hindered by proprietary, closed ecosystems, restricting real-time access to cloud services or vendor SDKs like the Huawei Wear Engine~\cite{huaweiWear}. To circumvent proprietary API barriers without cloud dependencies, mobile-mediated extraction techniques utilise accessibility service frameworks~\cite{androidAccessibility} to inspect screen node hierarchies and observe rendered companion-app UI states (e.g., Huawei Health). While an accessibility relay streams biometrics via local HTTP POST payloads, it does not provide a direct sensor API. 

This architectural constraint establishes an operational evidence ladder:
\begin{enumerate}[noitemsep,topsep=2pt]
  \item a value displayed on a wearable screen or companion application represents an upstream observation;
  \item an authenticated HTTP POST log at the local receiver confirms transport arrival;
  \item a validated bridge payload confirms compliance with the system's shared schema; and
  \item a rendered mirror card confirms local interface presentation.
\end{enumerate}
Downstream claims cannot assume data integrity based solely on upstream captures; each transition must be verified independently.

\section{Telemetry Freshness and Age of Information}
In networked monitoring systems, conventional performance metrics such as throughput and latency do not adequately describe the freshness of status updates. Kaul, Yates, and Gruteser~\cite{kaul2012realtime} introduced the \textit{Age of Information} (AoI) metric, defined as the time elapsed since the generation timestamp of the most recently received update:
\begin{equation}
\Delta(t) = t - U(t)
\end{equation}
where $U(t)$ is the generation time of the freshest sample available at time $t$. As demonstrated by Kosta et al.~\cite{kosta2017age}, simply maximizing throughput can degrade AoI due to buffer congestion and delivery delays.

In a wellness mirror interface, stale data represents a critical failure mode: presenting an outdated measurement as active physiological telemetry can mislead the user. The wellness mirror addresses this by tracking receiver arrival timestamps, value-change fingerprints, and transport link states. By enforcing dynamic state transitions across \texttt{LIVE}, \texttt{UNCHANGED}, \texttt{STALE}, and \texttt{OFFLINE} regimes---and automatically blanking values when arrival age exceeds an offline threshold---the interface prevents cached telemetry from being mistaken for live observations.

\section{Real-Time Scheduling and Embedded Telemetry}
Real-time operating systems (RTOS) partition software into prioritized, concurrent tasks with bounded release jitter. Liu and Layland~\cite{liu1973scheduling} established the foundational principles of rate-monotonic and fixed-priority preemptive scheduling for periodic hard-real-time tasks. In embedded microcontroller environments, such as the Espressif ESP32 dual-core SoC~\cite{espDevKit,espHardware}, FreeRTOS provides deterministic synchronization primitives, including message queues for thread-safe data transfer and mutexes with priority inheritance to prevent priority inversion~\cite{freertosQueues,freertosMutex}.

However, real-time claims must accurately reflect the host execution environment. When FreeRTOS v11 is executed as a Windows-hosted simulation process, the underlying non-real-time Windows kernel, host thread scheduling, and console I/O prevent the software from guaranteeing hard-real-time determinism. Under such conditions, task execution lateness, queue high-water marks, and missed-deadline counters function as observable diagnostic metrics for system evaluation rather than formal real-time proofs.

\section{Context-Grounded Conversational AI and Speech}
Recent advancements in large language models (LLMs) enable natural, conversational interaction in ambient interfaces. However, unconstrained LLMs are prone to hallucinations---generating fluent statements that contradict factual evidence or lack grounding~\cite{ji2023survey}. While Retrieval-Augmented Generation (RAG) retrieves unstructured document passages to ground knowledge-intensive queries~\cite{lewis2020rag}, edge-based wellness mirrors require structured parameter grounding: conditioning responses directly upon verified physiological metrics.

For voice interaction, edge-optimized implementations such as faster-whisper~\cite{fasterWhisper}, based on OpenAI's Whisper speech-recognition architecture~\cite{radford2023whisper}, enable private, local transcription using quantized integer arithmetic (\code{int8}). To ensure interaction safety in non-clinical settings, conversational guidance must be strictly bounded in length and validated by a rule-based consistency checker before delivery.

\section{Identified Engineering Gap}
Existing research offers robust models for smart mirrors, AoI-based queueing, and conversational AI in isolation. However, an engineering gap exists in integrating consumer wearable streams with ambient mirror interfaces when direct vendor APIs are unavailable:
\begin{itemize}[noitemsep,topsep=1pt]
  \item \textbf{Data Provenance Conflation:} Ambient dashboard prototypes often lack explicit provenance tagging, risking the conflation of synthetic or simulated test feeds with genuine human physiological observations.
  \item \textbf{Silent Stale Telemetry:} Conventional web dashboards frequently retain the last received measurement indefinitely upon sensor dropout or connection loss, without visible freshness indicators or automated blanking.
  \item \textbf{Ungrounded Conversational Output:} Conversational voice assistants deployed in wellness contexts rarely verify generated guidance against active on-screen physiological metrics, introducing potential hallucinations.
\end{itemize}

This minor project addresses this gap through a dual-pathway architecture isolating genuine wearable observations from deterministic synthetic telemetry, enforcing an eight-field validation contract, exposing freshness states, and verifying assistant guidance against sensor context.
